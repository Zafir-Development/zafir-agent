# History — хроника изменений Hermes Agent

Здесь хранится поэтапная история изменений архитектуры Hermes Agent в виде
снимков схемы. Каждый снимок — это законченный артефакт (исходник диаграммы,
готовый HTML и заметки), привязанный к ревизии `main`, на которой он снят.

## Структура

```text
history/
├── README.md
├── CHANGELOG.md                    # журнал: одна строка на этап
└── YYYY-MM-DD-<короткий-слаг>/     # снимок этапа
    ├── diagram.json                # исходник Archify (правим только новый снимок)
    ├── diagram.html                # отрендеренный самодостаточный артефакт
    ├── screenshot-light-*.png      # опционально: скриншот для быстрого просмотра
    └── NOTES.md                    # что изменилось, факты-источники, приёмка
```

## Как добавить этап

1. **Скопируйте предыдущий снимок** в новую папку `YYYY-MM-DD-<слаг>/` — так проще
   сохранить компоновку и изменить только то, что поменялось в агенте.
2. **Обновите `diagram.json`**: новые/удалённые компоненты, подписи, связи, карточки.
   Правило — сначала проверка по коду и документации (`AGENTS.md`, `website/docs/`),
   потом правка диаграммы.
3. **Соберите и проверьте HTML** (Archify, `--quality showcase`):

   ```bash
   node ~/.agents/skills/archify/bin/archify.mjs validate architecture \
     history/<слаг>/diagram.json --quality showcase --json
   node ~/.agents/skills/archify/bin/archify.mjs deliver architecture \
     history/<слаг>/diagram.json history/<слаг>/diagram.html --quality showcase --json
   node ~/.agents/skills/archify/bin/archify.mjs visual-check \
     history/<слаг>/diagram.html --json
   ```

   Приёмка: `validate` — 9/9 проверок, 0 ошибок, 0 предупреждений; `visual-check` —
   pass на 1440×900, 1600×1000, 1920×1080, 2048×1320.
4. **Заполните `NOTES.md`**: ревизия `main`, что изменилось, какие факты проверены
   (пути и строки), SHA-256 спецификации и артефакта, известные упрощения.
5. **Добавьте строку в `CHANGELOG.md`** (сверху, новые записи первыми).
6. **Закоммитьте в `main`** одним коммитом вида
   `docs(history): snapshot <слаг>`.

## Правила

- **Append-only.** Прошлые снимки не переписываются: если схема была неверной,
  следующий снимок исправляет её и фиксирует причину.
- **Один снимок = один этап.** Не смешивайте в одном снимке несвязанные доработки.
- **Факты важнее картинки.** Каждый узел и связь должны опираться на код или
  документацию; в `NOTES.md` указывайте источник.
- **Артефакт самодостаточен.** `diagram.html` открывается без сервера и зависимостей;
  он и есть публикуемая версия схемы.
